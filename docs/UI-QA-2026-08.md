# UI and interaction QA — August 2026

## User story

A first-time user can understand the board, add a product or personal image, get an automatic furniture cutout, move and edit the piece, compare the original and cutout, share the board URL, and return later without losing local work.

## Verified release checks

- TS swallow logo renders in the board header, favicon, extension popup, and Chrome extension icon set.
- Guided demo moves through choose, background-removal progress, and styling steps.
- Product search and Seating/Tables filters show the expected catalog items.
- A demo product is placed on the board and automatically receives a cutout.
- Original/Cutout comparison controls work.
- Title and price edits survive a full page refresh through IndexedDB persistence.
- Budget and collected-piece totals reflect saved products.
- Upload controls accept a local image and add it without running furniture removal.
- Share board copies a predictable local link and shows plain-language feedback.
- Room View is visibly marked as a next-phase feature instead of behaving like a dead control.
- The board-mode toolbar starts minimized, expands on demand, and returns to its compact state without covering the canvas.
- Removing a piece requires a clear confirmation dialog; choosing **Keep it** leaves the board unchanged.
- Background removal begins warming its on-device model when the board opens, reducing the wait after the first product action.
- Production web build, extension build, monorepo typecheck, and nine extraction tests pass.
- Production browser console has no application errors after a clean build.

## Known first-run behavior

The first real product cutout downloads and initializes the on-device ORMBG model. The interface shows progress and keeps the original safe. The worker now stays warm for later images, and the browser cache is reused across visits.

## Demo acceptance criteria

- A presenter can complete the guided board story without guessing which control to use.
- No dead settings, fake dropdown, or active future-mode controls appear.
- No crash, error overlay, or stale build artifact appears in a clean production session.
- Every user-facing failure message explains that the original or board remains safe.
